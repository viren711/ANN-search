--------------------------------------------------------------------------------
Goal: build ANN indices over three 128-d datasets, measure recall against EXACT
search (not BEIR relevance judgements), and compare our own Vamana against FAISS HNSW.

Datasets
  * SIFT1M : 1M x 128 base, 10K queries, supplied exact top-100 GT, L2 distance.
  * Quora  : 522,931 x 1024 Cohere-v3 corpus embeddings, 10,000 test queries.
  * NQ     : 2,681,468 x 1024 corpus embeddings, 3,452 test queries.
  * Quora/NQ -> PCA to 128-d: fit on corpus only (a random sample is allowed; report the
    size and seed), apply the same transform to corpus + queries, cast to float32, and
    L2-normalise. Every experiment uses these 128-d vectors.
  * GT: SIFT1M uses the supplied GT (check that FAISS agrees). Quora/NQ use FAISS exact
    search on the 128-d vectors, saved once and reused.
  * Metrics: 1-recall@1 and 10-recall@10 = mean |A_k ∩ G_k| / k.
  * SIFT100K dev set (a subset of SIFT1M with its own FAISS GT) for debugging and ablations.

Part 2 (implement ourselves; no Vamana/DiskANN libraries allowed)
  GreedySearch (must return the visited set V and count expansions and distance evaluations),
  RobustPrune(alpha, R), and the Vamana build: random R-regular init, entry point = the point
  nearest the mean, two passes (alpha=1 then alpha). Reference config R=64, L_build=100, alpha=1.2.
  Must scale to millions of points: compiled/vectorised code, compact int arrays, parallelism.
  Must measure build time at 100K / 250K / 500K before full builds.
  Report: R, L_build, alpha, build time, avg/max out-degree (max <= R!), serialized size,

Timing rules: same threads and query mode for every method, warm-up, index load excluded,

4. PART 2 — VAMANA IMPLEMENTATION                     (ann/vamana.py — own code)
--------------------------------------------------------------------------------
[x] 4.1 GreedySearch    _greedy_search: sorted bounded candidate list (size L) with an
        "expanded" flag and a pointer to the closest unexpanded candidate; returns the
        visited set V with distances; counts vertices expanded and new distance evaluations.
[x] 4.2 RobustPrune     _robust_prune: pool = (V ∪ N_out(p)) \ {p}, deduplicated, sorted by
        distance to p. Occlusion rule alpha*d(p*,p') <= d(p,p'), implemented as
        alpha^2 * d²(p*,p') <= d²(p,p') because distances are squared L2 internally.
[x] 4.3 Build           random R-regular init (seeded), entry point = the point nearest
        the mean, passes alpha = 1.0 then alpha, random permutation per pass, back edges
        with prune on overflow.
        - mode="serial": the literal pseudocode.
        - mode="batched" (default): parallel batch insertion (as in DiskANN/ParlayANN).
          Batch points search and prune concurrently on a read-only graph, then commit.
          Back edges are then grouped by target so each target has one owner thread
          (race-free). Batch sizes double from 1 up to 2% of N.
        Checked on a 20K subset (R=32, L=50): serial 10-R@10 = 0.9948 vs batched 0.9953
        at L_search=50, so the parallel build loses nothing.
[x] 4.4 Representation / optimisations
        - Numba @njit(fastmath, parallel, cache). The distance loop is SIMD-vectorised.
        - Vectors: contiguous float32 [N,128]. Graph: fixed-width int32 [N,R] + int32 degrees.
        - Per-thread int32 visited-tag arrays with epoch counters, so no O(N) clearing per search.
        - prange over queries / batch points / back-edge targets.
        - Deterministic seeds (graph init seed 0, permutations seed 1).
[x] 4.5 Unit sanity: no self loops, no duplicate edges, max out-degree <= R (asserted).
[x] 4.6 SIFT100K reference build (R=64, L_build=100, alpha=1.2, 12 threads):
        build 14.6 s, avg out-degree 53.43, max 64, min 7, graph 24.8 MiB (26.0 MB),
        peak RSS 378 MiB.
[x] 4.7 Single-query check (SIFT100K q0, L_search=50) ... scripts/sanity_query.py
        exact top-10 == Vamana top-10 = [36538, 36267, 2176, 3752, 68299, 49874, 882,
        87578, 4009, 2837]; 10-recall@10 = 1.0; 52 vertices expanded; 1618 distance evals.
[x] 4.8 Scaling test 100K/250K/500K of SIFT1M ........... scripts/scaling_test.py

6. EXTRA CREDIT — disk-resident DiskANN       (ann/diskann.py, ann/pagecache.py)
--------------------------------------------------------------------------------
[x] 6.1 MS MARCO support: download_data.py / prepare_beir.py --dataset msmarco
        (8.84M passages, ~18.8 GB parquet, dev split = 6,980 queries, same PCA-128 recipe)
[x] 6.2 Disk layout (scripts/ec_build_disk_index.py), DiskANN-style sector packing:
        record = [128 x f32 vector | i32 degree | R x i32 nbrs] = 772 B, 5 records per 4 KiB
        sector, no record crosses a sector; offset(v) = (v//5)*4096 + (v%5)*772.
        In RAM only: FAISS PQ codes (M=32 -> 32 B/vector, ~283 MB for MS MARCO), PQ centroids,
        entry point, an int32 visited-tag array, and per-query buffers.
[x] 6.3 Beam search (W=4): candidate list ordered by PQ distance; each round fetches the
        W closest unexpanded vertices' sectors together; exact distance from the on-disk vector;
        final top-k = expanded vertices re-ranked by exact distance.
        I/O mode "fadvise" (default): WILLNEED on all W sectors, then pread -> W reads in flight.
        SIFT100K NVMe test, L=50: fadvise warm 0.77 / cold 1.48 ms; threads 1.93 / 2.44;
        serial 0.72 / 2.02. POSIX_FADV_RANDOM disables readahead.
[x] 6.4 Cold/warm driver (scripts/ec_cold_warm.py): fincore -> fadvise(DONTNEED) per file ->
        fincore -> new process runs the timed workload. Warm = exercise run, then timed run.
        Search process capped with setrlimit(RLIMIT_AS = 8 GiB). Reports recall, mean/p50/p95,
        QPS, reads, bytes, rounds and expansions per query, kernel storage bytes/query
        (/proc/self/io), and peak RSS.
        Verified on SIFT100K: residency 0% before cold; cold reads hit storage, warm reads
        storage 0 B; recall identical to in-memory Vamana (0.995 @ L=50); peak RSS ~160 MiB.

Observations
 * Our Vamana matches or beats FAISS HNSW at equal recall on SIFT100K, e.g. 0.9926
   10-R@10 at 0.085 ms vs HNSW 0.9934 at 0.107 ms. Vamana is ~2x slower to build
   (14.6 s vs 5.0 s), mainly because of the two passes and L_build=100.
 * Expansions ≈ L_search (a property of GreedySearch). Distance evaluations grow
   sub-linearly in L because the neighbourhoods of consecutive expansions overlap.
 * After pass 1 (alpha=1) the average degree is only ~19. The alpha=1.2 pass adds long-range
   edges and raises it to ~53. That second pass costs ~2x as much as the first.
 * Index size: graph 26.0 MB + vectors 51.2 MB = 77.2 MB, close to HNSW M=32 (78.4 MB).
